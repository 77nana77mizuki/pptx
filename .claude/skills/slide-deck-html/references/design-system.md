# デザインシステム（タイポグラフィ・余白・配色トークン）

出典: 実成果物レビューで判明した課題——フォントサイズ（16px, 18px, 22px, 40px…）や余白がページごとに場当たり的に決められ、デッキ全体で統一感がなかった。トップティアのプレゼン資料（Apple基調講演、大手コンサルの提案資料等）は、個々のページを作る前にタイプスケール・スペーシング・配色の「トークン」を決め、全ページがそこから値を引く。ページごとに数値を決め直さないことが、素人っぽさと"整った感じ"を分ける最大の要因の一つ。

このファイルは値そのもの（何pxか、何色か）を固定するものではなく、**「決め方の型」**を提供する。実際の値はブランド・案件ごとに決め、決めたら全ページ・全スキル（`data-graphics` / `svg-story-animation`）で使い回す。

## タイプスケール

基準サイズ（例: 16px）に比率（1.25〜1.333程度）をかけた段階を先に決め、各ページで「だいたいこのくらい」と感覚で決めない。

| トークン | 用途 | 目安（1600×900ステージ） |
|---|---|---|
| `--fs-kicker` | 章番号チップ、アイキャッチのラベル | 14–16px、レタースペース広め、`text-transform: uppercase`（英字のみ） |
| `--fs-body` | 本文 | 20–22px |
| `--fs-body-lg` | やや強調した本文・リード文 | 24–26px |
| `--fs-h3` | 図中の小見出し・軸ラベル | 28–32px |
| `--fs-h2` | セクション見出し | 40–48px |
| `--fs-h1` | スライドタイトル（メッセージライン） | 56–72px |
| `--fs-statistic` | 統計ヒーロー用の巨大数字（[layout-gallery.md](layout-gallery.md)参照） | 180–260px |

**数字の扱い**：和文フォントに混ぜる数字は `font-variant-numeric: tabular-nums` を当て、桁が揃うようにする。統計ヒーローのような「数字が主役」のページでは、和文ゴシックの数字よりも幾何学的なサンセリフの数字（Google FontsのInter, Manrope等）を数字部分だけ当てると、より力強く読める（和文と英数字でフォントを分けるのはむしろ標準的なテクニック）。

**行間**：本文は1.5〜1.7、大見出しは1.3〜1.4を目安にする。文字が大きいほど行間を詰めるのは欧文タイポグラフィの慣習だが、日本語は詰めすぎると漢字の視認性が落ちるため欧文ほど極端に詰めない。

## 余白・グリッド

1600×900ステージに対して、外周のセーフマージンを決めておく（例：左右96px、上下72px）。第一階層のコンテンツ（タイトル・主要な図）はこの内側に収める。値は8pxを基準としたスペーシングスケール（8 / 16 / 24 / 32 / 48 / 64 / 96px）から選び、「ここは34pxで」のように任意の値を都度作らない。

```css
:root {
  --space-1: 8px;  --space-2: 16px; --space-3: 24px;
  --space-4: 32px; --space-5: 48px; --space-6: 64px; --space-7: 96px;
  --safe-x: var(--space-7); --safe-y: var(--space-6);
}
```

## 配色トークン（色そのものではなく「役割」を決める）

案件のブランドカラーが決まったら、以下の役割に割り当てる。数を増やしすぎない——役割が増えるほど「結局どこを見ればいいか」が薄まる（`data-graphics`の「アクセントカラーは1〜2箇所」と同じ理由をデッキ全体のUIにも適用する）。

```css
:root {
  --ink: #14203a;         /* 主要テキスト */
  --ink-soft: #5b6b85;    /* 補助テキスト・キャプション */
  --bg: #ffffff;          /* キャンバスの基調 */
  --panel-bg: #f3f6fb;    /* 副次パネル・カード面 */
  --line: rgba(20,32,58,.18); /* 罫線・区切り線 */
  --accent: #f2a900;      /* 強調・行動喚起。1色に絞る */
  --accent-secondary: #2d7dd2; /* 使うなら1箇所のみ。基本は無くても成立する */
}
```

ナビゲーションチロム（進捗バー・前後ボタン）や図表のアクセントカラーも、ここで決めた `--accent` を使い回す。ページごとに違う「映える色」を選ばない。

## 角丸・シャドウの規律

角丸は1〜2段階（例：`--radius-sm: 4px`、`--radius-md: 12px`）に絞り、要素ごとに違う丸みを与えない。影は「フレームワークの初期値をそのまま使った」ように見える濃いドロップシャドウを避け、使うとしても控えめな1段階（`box-shadow: 0 1px 3px rgba(20,32,58,.08)`程度）に留めるか、影の代わりに1pxのヘアラインボーダーで面を分ける方が端正に見える。カード＋厚い影＋大きな角丸の組み合わせは[visual-slop-lexicon.md](visual-slop-lexicon.md)が指摘する典型的な「量産テンプレ感」の一つ。

## 適用

- `data-graphics`（[charts.md](../../data-graphics/references/charts.md) 等）のフォントサイズ・余白は、ここで決めたトークンから選ぶ。ページごとに16/18/22/40のような数値を独自に決めない。
- `svg-story-animation`（[storytelling-patterns.md](../../svg-story-animation/references/storytelling-patterns.md)）の `var(--blue)` 等の色変数は、ここで決めた `--accent` / `--ink` 系の役割に対応づける。
- レイアウトの型は[layout-gallery.md](layout-gallery.md)、視覚的な「テンプレ感」を避ける観点は[visual-slop-lexicon.md](visual-slop-lexicon.md)を参照。
