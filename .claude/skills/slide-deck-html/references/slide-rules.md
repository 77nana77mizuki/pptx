# スライド作成ルール正典（このプロジェクト版）

出典: `carnot-tech/consulting-pptx-skill`（MIT License, github.com/carnot-tech/consulting-pptx-skill）の `references/slide-rules.md`（実務レビュー由来・約80項目の規約）。元の規約はPPTX／印刷・pt単位・軸のある表組みなど、経営会議向けの静的な配布資料を前提にしている。本プロジェクトは1600×900固定ステージ・SVGアニメーション付きの単一HTML（ブラウザで動かして見せる）という別の形式なので、**元の規約のうち形式に依存しない部分だけを移植・翻案**した。表組みの詳細書式やPPTX固有の検査（roundRect禁止、EMU単位など）が必要な案件では、元リポジトリを直接使うほうがよい。

他のドキュメントと食い違う場合はこのファイルが勝つ。指摘を受けたら該当の節に1行追記する（元リポジトリと同じ「指摘を規約に還元する」運用）。

## 1. タイトル（メッセージライン）

1. **結論をタイトルに書く。** 分類ラベル（「背景・課題」「ロードマップ」だけ）で終えず、そのページの主張を一文で書く。「背景・課題：」のような見出しラベルを前置きしない — ページの話題は左上のキッカー（章番号チップ）が担い、タイトルは主張文だけにする。
2. **常体で書く。** 「です」「ます」で終えない。主語と述語のある一文にする。
3. **普通の文として読めること。** スローガン調に圧縮しない。「この」「その」で他ページを参照しない（1枚で自立させる）。
4. **ページの中身の個数をタイトルの主役にしない。** 「3つの理由」より、その中身（結論・構造）を書く。数字を書いてよいのは、その数自体が伝えたい内容のとき（「価格は8倍以上開く」等）。
5. **タイトルだけを上から通し読みして、1本のストーリーになっているか確認する。** 全ページのタイトルを抜き出して読み、話が飛んだり同じ主張を繰り返していないかを見る。
6. **2行にするときは意味の切れ目で改行し、末尾1〜3字だけが残る泣き別れを作らない。**
7. **`<br>` で仕込んだ改行は、実際のレンダリング幅で必ず検証する。** 文字数だけを見て「大体2行に収まるはず」で `<br>` を置くと、フォントサイズとコンテナ幅（`padding` を引いた実効幅）の見積もりを外し、ブラウザがその区間をさらに自動折り返しして3〜4行に化けることがある。しかもその追加の折り返しは意味の切れ目を無視するため、単語の途中（「ほど、」→「ほ／ど、」、「見えにくく」→「見えに／くく」等）で割れる最悪の改行が生まれる。ヘッドレスブラウザで `Range.getClientRects()` 等を使い、`<br>` で区切った各区間が実際に1行に収まっているかを確認してから確定する。収まらない場合は、区切り位置を変えるのではなく、まずタイトルのフォントサイズ／コンテナ幅の設計を疑う（1600×900のような固定幅レイアウトでは1行あたりの許容文字数が固定されるため、想定文字数に対してフォントサイズが大きすぎるのが根本原因であることが多い）。

## 2. レイアウトと1ページ1メッセージ

1. **1スライド＝1メッセージ。** 伝えたいことが2つあるなら2ページに分ける。
2. **図（アニメーション）と文章の主張を一致させる。** 中心のSVGアニメーションが表現している仕組み（収束・パルス・変換・循環・成長・分岐・進行）と、タイトル・本文が主張している内容が食い違っていないか、仕上げ時に必ず照合する。図だけで結論が出ていて本文が余計なことを言っている、あるいはその逆は典型的な破綻。
3. **チャート・図があるページは、事実の提示だけで終えない（So what）。** 「何が起きているか」の図に対して、「だからどうなのか」を一言添える。置き場所はタイトルが基本。
4. **左右2カラムを使うときは、前提・理由を左、具体・結果を右に置く。** 読み手は左から右に「なぜ→何が」の順で読む。
5. **並列要素は粒度・主語を揃える。** 「担当者が作る」と「自動生成される」のように主体がバラバラな並列を作らない。
6. **囲み・帯・フローティングラベルを乱用しない。** ラベルやチップを版面に浮かせて置かず、必ず図の構造（ノード・軸・パス）の中に組み込む。

## 3. 文章・語尾

> 元リポジトリの `ai-smell-lexicon.md` をほぼそのまま同梱している（[vendored/ai-smell-lexicon.md](vendored/ai-smell-lexicon.md)）。文章を書き終えたら、この語彙リストで30秒セルフチェックする。

1. **AI臭ワードを消す。** 空虚な強調（まさに／非常に／極めて）、カタカナ盛り（ソリューション／シナジー）、名詞句化ビジネス語（最適化／効率化／推進）、定型の枕（変化の激しい時代において）などは書いた後に見直して削る。
2. **ブレットの語尾は階層内で統一する。** 体言止めなら全部体言止め、動詞止めなら全部動詞止め。
3. **主語と述語を落とさない。** 「〜の強化」のような名詞に畳んだ表現でなく、「誰が何をする」まで書く（字数を削るときは修飾語から削る）。
4. **略語は初出でフル表記に併記してから使う。** 1資料の中で同じ概念に複数の表記（例：ユーザー／利用者）を混在させない。

## 4. 出力前の機械チェック

PPTX/印刷向けの元チェック（`check_deck.py`）はそのまま使えないため、このプロジェクトでは以下を目視＋簡易grepで代替する。

- [ ] タイトルにプレースホルダー（`〇〇` / `Text N` / `YYYY` 等）が残っていない
- [ ] 全ページのタイトルを抜き出して通し読みし、1本のストーリーとして成立するか（分類ラベルだけのタイトルが混じっていないか）
- [ ] `<section class="slide">` の数とページ番号表示（`〇 / 全体数`）が一致しているか
- [ ] 各ページで、中心アニメーションが表現している仕組みとタイトル・本文の主張が一致しているか
- [ ] ですます調・AI臭ワードが本文に残っていないか（[vendored/ai-smell-lexicon.md](vendored/ai-smell-lexicon.md) で確認）
- [ ] 可能ならヘッドレスブラウザ（Playwright等）で全ページをレンダリングし、テキストのはみ出し・要素の重なり・ステージ外へのクリップがないかスクリーンショットで確認する（`references/stage-and-navigation.md` 参照）
- [ ] タイトル・見出しに手動で `<br>` を入れている場合、各区間が実際に1行で収まっているか（§1-7）をヘッドレスブラウザで検証する。日本語は文字間にスペースがなく、フォントサイズとコンテナ幅から1行の文字数上限がほぼ決まるため、文字数の目算だけで改行位置を決めると、意図しない追加の自動折り返しで単語途中の改行が発生しやすい

## 5. フレッシュアイ・レビュー（最終工程）

詳しい手順とコピー用の指示文は [review-prompt.md](review-prompt.md) にある。要点は、**作った本人には見えない破綻を、条件を伏せた別のエージェント（新規セッションやAgentツール）にデッキそのものを読ませて拾わせる**こと。機械チェックを通した後、納品前に必ず1回通す。指摘は採否表にして、採用分だけ直す。
