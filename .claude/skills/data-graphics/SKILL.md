# データグラフィックス（表・グラフ・タイムライン）

このスキルは、データを「正しく構造化して見せる」ことだけを担当します。完成形は静止画（アニメーションなし）が前提で、`slide-deck-html` の固定ステージにも、単体のインフォグラフィックにも組み込めます。特定のスライド構造には依存しません（疎結合）。

参照元：
- Financial Times `chart-doctor` の Visual Vocabulary（github.com/Financial-Times/chart-doctor）— 「比較／推移／構成比／相関／分布／偏差」というデータの関係性からチャート種類を選ぶ分類法
- Cleveland & McGill (1984) の知覚精度階層（位置＞長さ＞角度＞面積＞色）— NTCoding/claude-skillz の `data-visualization` スキルが整理を引用しており、本スキルもこの優先順位を採用
- Cole Nussbaumer Knaflic『Storytelling with Data』— グラフ・表の「デクラッター」原則（枠線・グリッド線・凡例を削り、直接ラベリングする。表は縁取りと網掛けを削る）
- `cathrynlavery/diagram-design`（MIT License）— タイムライン・ガントを含む自己完結HTML＋SVG図の設計思想（「装飾のためだけの要素を置かない」「アクセントカラーは1〜2箇所に絞る」）。コードは流用せず、思想と構造だけを本プロジェクトの1600×900ステージ向けに再構成した

## 作る前に：3つの問い

1. **何を伝えたいか？** 比較／推移（時系列）／構成比／相関／分布／偏差 のどれか。2つ以上あるなら図を分ける（`slide-deck-html` の「1スライド1メッセージ」と同じ理由）。
2. **表・グラフ・タイムライン系のどれが適切か？** 個々の正確な値を読み取らせたいなら表、パターンや傾向の"形"を見せたいならグラフ、期間・フェーズ・工程の並びを見せたいならタイムライン系。迷ったら下の使い分け表を見る。
3. **動きで説明する必要があるか？** プロセスが「進む」「変化する」ことそのものを見せたいなら `svg-story-animation` の該当パターン（成長・段階的進行など）を併用する。それ以外は静止画で完成させる——動かせば伝わるはずという発想は情報を隠すサインになりやすい。

## 表・グラフ・タイムライン系の使い分け

| 種類 | 得意なこと | 向いている場面 |
|---|---|---|
| **表** | 個々の値を正確に読み取らせる、複数指標を横並びで比較する | 少数の項目・複数列の詳細な数値、意思決定に使う具体的な数字 |
| **グラフ**（棒／折れ線・面／ドーナツ） | パターン・傾向・大小関係を直感的に伝える | 比較、推移、構成比を"形"で見せたいとき |
| **タイムライン／ロードマップ／ガント** | 期間・順序・並行関係を見せる | 沿革、計画、工程表、フェーズの前後関係 |

## 設計原則（要約。詳細は各referencesファイル）

- **知覚精度の高い順にエンコードする**：位置＞長さ＞角度＞面積＞色（Cleveland & McGill）。色や面積だけで大小を比較させない。
- **データインク比を上げる**：枠線・グリッド線・凡例を削り、値やラベルを図形の直近に直接置く（Knaflic）。
- **アクセントカラーは1〜2箇所だけ**。伝えたい1点だけを強調し、他はニュートラルなトーンに落とす。
- **色だけに頼らない**。形・パターン・直接ラベルを併用し、色覚特性に依存しない見分け方を用意する。
- **円グラフは4区分まで**。5区分を超えたら棒グラフに置き換える。
- **数値は実データから**。丸め・単位・小数点桁数をページ内で統一し、部分の合計が全体と一致するか検算する。

## このスキルが担当しないこと

- 図に動きで仕組み（成長・循環・分岐など）を説明させる演出 → `svg-story-animation` の領分
- スライドの入れ物・ナビゲーション・進捗バー・密度モード → `slide-deck-html` の領分
- 色のパレット設計そのもの（色相・コントラストの数理的な決め方）→ 環境に `dataviz` スキルがあればそちらを併用してよい。本スキルはどのパレットが来ても成立するエンコーディングの設計だけを扱う
- PowerPoint／PDF変換、配布まわり → 対象外
