# 外部ライブラリを検討する基準（エスケープハッチ）

このプロジェクトは外部依存のない単一HTMLファイルが要件であり、既定の選択はネイティブSVG（SMIL）とCSSである。ここに書かれているのは「基本はライブラリ不要」という方針を崩さないための、**例外を認める条件**と**認めた場合の埋め込み方**。

## 2026年時点のライブラリ地形（参考）

- **GSAP**：2024年10月にWebflowが買収し、2025年5月にMorphSVGPlugin・DrawSVGPlugin・ScrollTriggerを含む全プラグインが無料化された。スクロール連動の複雑な振り付け（ピン留め、スクラブ、タイムライン同期）や、頂点数の異なる形状同士の本格的なモーフィングで最も実績がある。
- **flubber**（MIT License）：形状の頂点数・穴・サブパス数が異なっていても補間できる、モーフィング専用の軽量ライブラリ。GSAPほど高機能ではないが依存が小さい。
- **anime.js v4**：軽量（約17KB gzip）。単発〜数個の自己完結したアニメーションに向くが、本プロジェクトが必要とするのはSMILで大半代替できるため優先度は低い。
- **Motion（旧Framer Motion）**：Reactエコシステム向け。フレームワーク非依存の単一HTML要件とは前提が合わない。
- **Lottie / Rive**：After Effectsで作った複雑なベクターアニメーションの再生や、状態遷移を持つインタラクティブなキャラクター・アイコンに向く。デザイナーがAEやRiveエディタで作った成果物を再生する用途であり、このスキルが担当する「コードで組み立てるストーリーテリング」とは制作フローが異なる。

## 検討して良い条件

以下のいずれかに該当するときだけ検討する。該当しない限りネイティブSMIL/CSSで書く。

1. **モーフィング元・先の構造差が大きすぎる**（頂点数が2倍以上違う、穴がある、サブパス数が違う）。[references/fundamentals.md](fundamentals.md)の「不可視の中間点を手で足す」対処が非現実的な場合 → **flubber**を検討。
2. **本物の物理ベースのバネ（複数回の減衰振動）が要件にある**。[references/storytelling-patterns.md](storytelling-patterns.md)パターン19の`keySplines`多段近似では表現力が足りない場合 → **GSAP**の`elastic`/`bounce`イージングを検討。
3. **複雑なスクロール演出**（要素をピン留めしたまま別の要素をスクラブする、複数セクションのタイムラインを1本のスクロールに同期させる）で、CSS `animation-timeline: scroll()/view()` の単純なマッピングでは足りない場合 → **GSAP ScrollTrigger**を検討。

**判断に迷ったら、まずネイティブで書いてみて、実際に破綻するかを確認してから導入する**。「重い処理をあらかじめライブラリに任せておく」という予防的な導入はしない。

## 導入する場合の埋め込み方

単一HTMLファイル要件を壊さないために、CDNの `<script src="https://...">` ではなく、ライブラリのソース（minified版）を `<script>` タグの中に直接貼り付けてインライン化する。ネットワーク接続なしで動くことを確認する。ファイルサイズは増えるが、自己完結性は維持できる。ライセンス表記（GSAPの無料化条件、flubberのMIT表記など）が必要な場合は忘れずに残す。
