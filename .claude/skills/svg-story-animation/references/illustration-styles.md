# イラスト・ビジュアルモチーフのスタイルガイド

出典: 本プロジェクトの実成果物レビューで判明した課題（unDraw等の汎用フラットイラストの多用による「量産テンプレ感」）と、Pentagram・IDEOなど一流デザインスタジオの資料が「汎用ストックイラスト」ではなく「その資料固有の図解・タイポグラフィ」で構成される傾向を踏まえて作成。[references/storytelling-patterns.md](storytelling-patterns.md) が「動き」の引き出しなら、これは「静止した絵そのもの」の引き出し。

## 前提：なぜストックの人物イラストは「量産感」を生むか

unDraw / Storyset のような汎用フラットイラストは、配色をブランドカラーに変えても構図・ポーズ・小物が数万のサイト・資料で使い回されているため、見た瞬間に「テンプレに差し替えただけ」と伝わる。これは文章の [ai-smell-lexicon.md](../../slide-deck-html/references/vendored/ai-smell-lexicon.md)（AI臭ワード）の視覚版であり、理由も同じ——**中身のない体裁だけの丁寧さ**。1本のデッキの中で「その資料だけの絵」が1枚もないと、どれだけ文章を練っても資料全体が量産品に見える。

## 人物イラストに頼らない6つの語彙

同じ「仕組み」を説明するにも、必ずしも人物やシーンのイラストである必要はない。以下から、内容と相性の良いものを選ぶ。同一デッキ内で1〜2系統に絞り、混在させない。

### 1. 幾何学的抽象（ノード・線・面）

`storytelling-patterns.md` の視覚語彙（円＝ノード、線＝関係、塗り＝状態）をそのまま静止画にも使う。「人が話し合っている絵」の代わりに「2つの円が線でつながっている図」で協働を表す。抽象度が高い分、キャプションの言葉と強く結びつけて使う。

### 2. データ・アズ・アート — データそのものを絵にする

装飾のためのアイコンやイラストを添えるのではなく、**実際の数値・構造から絵の形を作る**。例：拠点数だけ円を並べて配置する、実績の推移をそのまま背景の線として使う、達成率をシルエットの塗り分けで表現する。`data-graphics` のチャートを「情報を読み取らせる図」として使い、こちらは同じ数値を「印象を残す絵」として再構成する用途の違いがある。

```svg
<!-- 例: 実際の拠点数(7)ぶんの円を、実在する地理配置に近い相対位置で描く -->
<g fill="var(--blue-mid)">
  <circle cx="120" cy="260" r="14"/><circle cx="220" cy="180" r="14"/><circle cx="340" cy="300" r="14"/>
  <circle cx="460" cy="150" r="14"/><circle cx="560" cy="260" r="14"/><circle cx="640" cy="120" r="14"/>
  <circle cx="720" cy="220" r="18" fill="var(--accent)"/>
</g>
```

### 3. タイポグラフィをビジュアルにする

大きな数字・短い単語・漢字1文字を画面の主役にし、イラストを一切使わない。「8倍」という結論があるなら、8を画面高の1/3〜1/2の大きさで置くだけで、どんなイラストより強く残る。コンサル資料・基調講演のキーメッセージページで多用される手法。

```svg
<text x="80" y="420" font-size="360" font-weight="800" fill="var(--ink)">8×</text>
<text x="90" y="480" font-size="28" fill="var(--ink-soft)">価格帯の広がり</text>
```

### 4. アイソメトリック／技術図解

システム構成・工程・物理的な仕組みを説明するときは、可愛らしいシーンではなく箱・層・矢印による技術図解（isometricの浮遊感がある平行投影、または真正面からのブロック図）を使う。装飾ではなく構造を見せることに徹する。

### 5. カスタム・モノラインアイコン

アイコンが必要なら、既製の「角丸四角＋ベタ塗りピクトグラム」アイコンパックではなく、中心アニメーションと同じ線幅・角の丸め方で自作する（下記「装飾要素の一貫性」参照）。1〜2px刻みで線幅を統一し、塗りではなく線（outline）中心にすると、動くSVGアニメーションと同じ手の運びに見える。

### 6. テクスチャ・背景

奥行きが欲しいときは、汎用のグラデーションブロブ（紫→青のぼんやりした光彩）ではなく、細かいドットグリッドや極薄の線グリッドを使う。装飾が「主張のための余白」になり、ネットワーク背景ほど主張が強くならない。

```svg
<pattern id="dotgrid" width="24" height="24" patternUnits="userSpaceOnUse">
  <circle cx="2" cy="2" r="1.5" fill="var(--ink-soft)" opacity="0.15"/>
</pattern>
<rect width="100%" height="100%" fill="url(#dotgrid)"/>
```

## 人物イラストがどうしても要るとき

証言・企業文化・「特定の人物の行動」を主語にした具体的なエピソードを扱うページなど、人が主役の内容には人物表現が向く場面もある。使う場合は以下を守る。

- **1つの描画スタイルに統一する。** unDrawと別素材、あるいはunDrawと自作ベクターの混在は禁止。1本のデッキは1つの「作家」が描いたように見えるべき。
- **配色だけでなく背景装飾も自作の意匠に揃える。** 配色をブランドカラーに変えただけで、背景のドットや線が元素材のままだと「借り物」感が消えない。
- **同じ構図をデッキ内で繰り返さない。** 「人＋ノートPC」のような構図を3回以上使うと、それ自体が新しい量産パターンになる。

## 装飾要素の一貫性（デッキ全体で意匠を使い回さない）

- **背景の点と線のネットワーク**：ヒーロー（表紙）とクロージングなど「始まりと終わり」の1〜2箇所に限定する。本編の全ページ背景に使い回すと単調かつ量産感が出る（`slide-deck-html` の [layout-gallery.md](../../slide-deck-html/references/layout-gallery.md) 参照）。
- **角丸四角＋ベタ塗りピクトグラムのアイコンタイル**：本当に識別記号として要る1箇所（章番号チップなど）に限定し、中心アニメーションの代役にしない。

## セルフチェック

- [ ] デッキ全体で人物イラストの構図・スタイルが1系統に統一されているか（複数のストック素材が混在していないか）
- [ ] 装飾（ネットワーク背景・アイコンタイル）が全ページで同じものの使い回しになっていないか
- [ ] デッキの中に少なくとも1ページは、人物イラスト以外の語彙（データ・アズ・アート／タイポグラフィ／幾何学的抽象）で表現されたページがあるか
- [ ] カスタムアイコンを作る場合、線幅・角の丸めが中心アニメーションと揃っているか（意匠がバラバラに見えないか）
- [ ] 「これはどこかで見たことがある」という既視感がないか——既視感があれば大抵、汎用ストック・汎用アイコンパックのどちらかに当てはまる
